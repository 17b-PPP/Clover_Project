1. ภาพรวมของโปรเจกต์ (Project Overview)

Clover Project (Field Latex) คือระบบจัดการการรับซื้อน้ำยางพาราสำหรับ สหกรณ์กองทุนสวนยางบ้านบางบอนจำกัด โดยรองรับการทำงาน 2 กลุ่มผู้ใช้หลัก:

กลุ่มผู้ใช้ บทบาท การเข้าสู่ระบบ
พนักงาน/ผู้ดูแลระบบ (Staff/Admin) จัดการสมาชิก ลูกจ้าง สัญญาจ้าง รับซื้อน้ำยาง เบิกเงิน Username + Password ผ่านหน้า /login
สมาชิก (Member) ดูประวัติการขายน้ำยางและยอดเงินสะสมของตนเอง เลขบัตรประชาชน + วันเกิด ผ่านหน้า /member/login

เทคโนโลยีหลัก

หมวดเทคโนโลยีรายละเอียด
FrameworkNext.js 16 (App Router)ใช้ Server Components เป็นหลักสำหรับดึงข้อมูลฝั่งเซิร์ฟเวอร์
ภาษาTypeScriptType-safe ทั้ง Frontend และ Backend
StylingTailwind CSSUtility-first CSS framework
ORMPrismaObject-Relational Mapping สำหรับจัดการฐานข้อมูล
DatabasePostgreSQLฐานข้อมูลหลักผ่าน Supabase (ดูจาก directUrl ใน schema)
FontNoto Sans Thaiฟอนต์ภาษาไทยจาก Google Fonts

2. สถาปัตยกรรมระบบ (System Architecture)

ระบบใช้สถาปัตยกรรมแบบ 3 ชั้น (Three-Tier Architecture) ภายใน Next.js Monolith:

┌───────────────────────────────────────────────────────┐ │ PRESENTATION LAYER │ │ ┌─────────────┐ ┌─────────────┐ ┌──────────────┐ │ │ │ Server Page │ │ Client Page │ │ UI Comps │ │ │ │ (page.tsx) │──│ (*Client.tsx)│──│ (Modal,Table)│ │ │ └──────┬──────┘ └──────┬──────┘ └──────────────┘ │ │ │ │ │ ├─────────┼────────────────┼────────────────────────────┤ │ │ BUSINESS LOGIC LAYER │ │ │ │ │ │ ┌──────▼──────┐ ┌──────▼──────┐ ┌──────────────┐ │ │ │ Direct Call │ │ API Routes │ │ Activity Log │ │ │ │ (SSR fetch) │ │ (/api/*) │──│ (audit trail)│ │ │ └──────┬──────┘ └──────┬──────┘ └──────────────┘ │ │ │ │ │ ├─────────┼────────────────┼────────────────────────────┤ │ │ DATA ACCESS LAYER │ │ │ │ │ │ ┌──────▼────────────────▼──────┐ │ │ │ lib/data/*.ts │ │ │ │ (Prisma queries, serialize) │ │ │ └──────────────┬───────────────┘ │ │ │ │ │ ┌──────────────▼───────────────┐ │ │ │ Prisma Client (lib/prisma) │ │ │ └──────────────┬───────────────┘ │ │ │ │ │ ┌──────────────▼───────────────┐ │ │ │ PostgreSQL DB │ │ │ └──────────────────────────────┘ │ └───────────────────────────────────────────────────────┘

Data Flow ที่สำคัญ 2 รูปแบบ

รูปแบบ ใช้ตอนไหน ตัวอย่าง
SSR Direct Call โหลดข้อมูลครั้งแรกเมื่อเปิดหน้า (Server Component เรียก lib/data/*.ts โดยตรง) page.tsx → getMembers()
Client-side API การ CRUD จากฝั่ง Client (กดปุ่ม สร้าง แก้ไข ลบ) ผ่าน fetch() ไปยัง API Routes *PageClient.tsx → fetch('/api/members')

4.4 Prisma Client Singleton

ไฟล์ lib/prisma.ts ใช้ Global Singleton Pattern เพื่อป้องกันการสร้าง Prisma Client ซ้ำหลายครั้งในโหมด Development (Hot Reload):

const globalForPrisma = globalThis as unknown as { prisma: PrismaClient | undefined };
export const prisma = globalForPrisma.prisma ?? new PrismaClient();
if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = prisma;
}

5. รูปแบบการดึงข้อมูล (Data Fetching Patterns)

5.1 Pattern หลัก: Server-Side Direct Import

ทุกหน้าเพจหลัก (page.tsx) เป็น Server Component ที่เรียก Data Access Layer โดยตรง:

// app/(app)/members/page.tsx
import { getMembers } from "@/lib/data/members";

export default async function MembersPage() {
  const members = await getMembers();
  return <MembersPageClient initialMembers={members} />;
}
💡 ข้อสังเกต — Hybrid Rendering Pattern ข้อมูลเริ่มต้นถูกดึงที่ Server (ไม่ต้อง Loading State ครั้งแรก) จากนั้นส่งเป็น props ให้ Client Component เพื่อจัดการ State, Filtering, CRUD ต่อ

5.2 Data Serialization Pattern

ทุกไฟล์ใน lib/data/*.ts มีฟังก์ชัน serialize() เพื่อแปลง Prisma Object → Plain TypeScript Object:

Prisma TypeSerialized Typeเหตุผล
DecimalnumberPrisma Decimal ส่งผ่าน JSON ไม่ได้ ต้องเรียก .toNumber()
DateTimestring (ISO)Date object ส่งผ่าน Server→Client boundary ไม่ได้ ต้องเรียก .toISOString()
// ตัวอย่างจาก lib/data/members.ts
function serialize(member: PrismaMember): Member {
  return {
    ...member,
    walletBalance: member.walletBalance.toNumber(),    // Decimal → number
    dateOfBirth: member.dateOfBirth.toISOString(),      // Date → string
    createdAt: member.createdAt.toISOString(),
  };
}

5.4 Performance Optimization: Selective Fields

ฟังก์ชัน getMembers() และ getEmployees() ใช้ select แทน findMany() ทั้งหมด โดย ไม่ดึง photoUrl เพื่อลดขนาด payload (รูปถ่ายเก็บเป็น Base64 Data URL ซึ่งมีขนาดใหญ่):

// lib/data/members.ts — getMembers()
const members = await prisma.member.findMany({
  select: {
    id: true, memberCode: true, firstName: true, ...
    // ❌ ไม่มี photoUrl
  },
});

เมื่อต้องการดูรูปถ่าย จะเรียก getMember(id) ที่ใช้ findUnique() เพื่อดึงข้อมูลครบทุกฟิลด์แทน

6.2 API Pattern ที่ใช้ซ้ำกันทุก Route

// โครงสร้างมาตรฐานของทุก API Route
export async function POST(request: NextRequest) {
  try {
    // 1. Parse body
    const body = await request.json();

    // 2. Validate required fields
    const missing = requiredFields.filter(f => !body[f]);
    if (missing.length) return NextResponse.json({ error: ... }, { status: 400 });

    // 3. Business validation
    if (!isValidIdCardNumber(body.idCardNumber)) { ... }

    // 4. Call Data Layer
    const result = await createSomething(body);

    // 5. Log activity (Audit Trail)
    await logActivity({ action: "CREATE_*", ... });

    // 6. Return response
    return NextResponse.json(result, { status: 201 });
  } catch (error) {
    return handleRouteError(error);  // Centralized error handler
  }
}

6.3 Error Handling

ใช้ handleRouteError() จาก lib/api-error.ts เป็น Centralized Error Handler:

export function handleRouteError(error: unknown) {
  console.error(error);
  const message = error instanceof Error ? error.message : "Internal server error";
  return NextResponse.json({ error: message }, { status: 500 });
}

นอกจากนี้ยังมี Custom Error Classes สำหรับ Business Logic เฉพาะ:

  • SellerLookupError — ค้นหาผู้ขายไม่พบ (ใน purchases)
  • WithdrawalError — ยอดเงินไม่เพียงพอ / ค้นหาสมาชิกไม่พบ (ใน withdrawals)

7. Business Logic — จุดสำคัญ

7.1 ระบบรับซื้อน้ำยาง (Purchase System) ⭐

นี่คือ หัวใจสำคัญที่สุดของระบบ เพราะเกี่ยวข้องกับเงินและการคำนวณหลายขั้นตอน

สูตรการคำนวณ:

น้ำหนักยางแห้ง (dryWeightKg) = น้ำหนักน้ำยางสด (rawWeightKg) × %เนื้อยางแห้ง (dryPercentage) / 100
จำนวนเงินรวม  (totalAmount)  = น้ำหนักยางแห้ง × ราคากลาง (marketPrice)
ส่วนแบ่งลูกจ้าง (employeePayout) = totalAmount × employeeShare / 100  (ปัดเศษ 2 ตำแหน่ง)
ส่วนแบ่งเจ้าของ (ownerPayout)    = totalAmount - employeePayout  (คำนวณจากส่วนที่เหลือ เพื่อไม่ให้เกิดปัญหาเศษ)
⚠️ จุดสำคัญ — การปัดเศษ ส่วนแบ่งของลูกจ้างถูกปัดเศษ 2 ตำแหน่งก่อน จากนั้นส่วนแบ่งเจ้าของสวนคำนวณจาก totalAmount - employeePayout เพื่อรับประกันว่าสองส่วนรวมกันได้เท่ากับ totalAmount เสมอ

Seller Lookup Logic:

ฟังก์ชัน lookupSeller(code) ค้นหาผู้ขายจากรหัสที่ป้อน โดยมีลำดับการค้นหา:

  1. ค้นหาใน Member ก่อน — ถ้าเจอ ถือว่าเจ้าของสวนขายเอง (memberShare = 100%)
  2. ค้นหาใน Employee — ถ้าเจอ ค้นหา Active MePair เพื่อหาเจ้าของสวนและสัดส่วน
  3. ไม่เจอทั้งคู่ — Throw Error

Transaction Atomicity:

การสร้าง Purchase ใช้ prisma.$transaction เพื่อรับประกันว่า:

const [purchase] = await prisma.$transaction([
  prisma.purchase.create({ data: { ... } }),      // 1. สร้างรายการรับซื้อ
  prisma.member.update({                           // 2. เพิ่มยอดเงินสะสมให้เจ้าของสวน
    where: { id: seller.memberId },
    data: { walletBalance: { increment: ownerPayout } },
  }),
]);

7.2 ระบบเบิกเงิน (Withdrawal System)

คล้ายกับ Purchase แต่ทำงานย้อนกลับ:

const [withdrawal] = await prisma.$transaction([
  prisma.withdrawal.create({ data: { ... } }),    // 1. สร้างรายการเบิกเงิน
  prisma.member.update({                           // 2. หักยอดเงินสะสม
    where: { id: member.memberId },
    data: { walletBalance: { decrement: input.amount } },
  }),
]);
💡 การตรวจสอบก่อนเบิก
  • ตรวจว่าสมาชิกมีอยู่และสถานะ Active
  • ตรวจว่ายอดเบิก > 0
  • ตรวจว่ายอดเบิก ≤ walletBalance (ยอดเงินสะสมต้องเพียงพอ)

7.3 ระบบสัญญาจ้าง (Contract System)

การสร้างสัญญาใหม่:

  • ตรวจสอบทั้ง Member และ Employee ต้องมีสถานะ Active
  • ตรวจสอบไม่ให้มีสัญญาที่ยังใช้งานอยู่ (contractEndDate = null) สำหรับคู่เดียวกัน

การต่อสัญญา (Renew):

ใช้ $transaction เพื่อทำ 2 ขั้นตอนพร้อมกัน:

  1. ปิดสัญญาเดิม (set contractEndDate = now)
  2. สร้างสัญญาใหม่ด้วยสัดส่วนที่เปลี่ยน + contractStartDate = now

7.4 ระบบราคากลางน้ำยาง (Market Price Lock)

หน้ารับซื้อน้ำยาง (PurchasesPageClient) มีฟีเจอร์ ล็อกราคากลาง:

  • ราคากลางเก็บใน localStorage ด้วย key purchases:lockedMarketPrice
  • เมื่อล็อกแล้ว ราคาจะใช้ซ้ำทุกครั้งที่บันทึกรายการใหม่ ไม่ต้องกรอกซ้ำ
  • ราคาจะถูกล็อกอัตโนมัติหลังจากบันทึกรายการรับซื้อสำเร็จ

7.5 ระบบ Audit Log (Activity Logging)

ทุก API Route ที่ทำการเปลี่ยนแปลงข้อมูล จะเรียก logActivity() เพื่อบันทึกกิจกรรม:

await logActivity({
  action: "CREATE_PURCHASE",           // ActionType enum
  targetType: "PURCHASE",              // TargetType enum
  targetId: purchase.id,               // ID ของข้อมูลที่เปลี่ยนแปลง
  description: `บันทึกรับซื้อน้ำยาง ...`,  // คำอธิบายภาษาไทย
});

ฟังก์ชัน logActivity() จะดึง Session ปัจจุบันเพื่อบันทึก staffId ของผู้กระทำ

8.2 Session Encoding

ใช้ HMAC-SHA256 Signed Token (ไม่ใช่ JWT) ในรูปแบบ base64url(payload).signature:

function encodeSession(payload: SessionPayload): string {
  const json = Buffer.from(JSON.stringify(payload)).toString("base64url");
  const signature = crypto.createHmac("sha256", getSecret())
    .update(json).digest("base64url");
  return `${json}.${signature}`;
}
💡 ความปลอดภัยที่น่าสนใจ
  • ใช้ crypto.timingSafeEqual() เพื่อเปรียบเทียบ Signature (ป้องกัน Timing Attack)
  • Member Session ใช้ Derived Key ที่ต่างจาก Staff Session ทำให้ Token ของ Member ไม่สามารถใช้เป็น Token ของ Staff ได้
  • ตรวจสอบ exp ทุกครั้งที่ decode เพื่อป้องกัน Token หมดอายุ

8.3 Password Hashing

ใช้ scrypt (ไม่ใช่ bcrypt) จาก Node.js built-in crypto module:

// lib/auth.ts
export function hashPassword(password: string): string {
  const salt = crypto.randomBytes(16).toString("hex");
  const hash = crypto.scryptSync(password, salt, 64).toString("hex");
  return `${salt}:${hash}`;  // เก็บเป็น "salt:hash"
}

export function verifyPassword(password: string, stored: string): boolean {
  const [salt, hash] = stored.split(":");
  const candidate = crypto.scryptSync(password, salt, 64).toString("hex");
  return crypto.timingSafeEqual(Buffer.from(candidate, "hex"), Buffer.from(hash, "hex"));
}

8.4 Open Redirect Protection

หน้า Login มีฟังก์ชัน sanitizeNext() ที่ตรวจสอบ ?next= parameter อย่างรัดกุม:

  • ตรวจสอบว่า URL เป็น same-origin
  • ตรวจสอบ protocol-relative URL (เช่น //evil.com)
  • ตรวจสอบว่า path เป็น "fixed point" ของ parser (ไม่ถูก normalize เป็น URL ที่ต่างออกไป)

13.1 สิ่งที่ต้องตั้งค่า (Environment Variables)

ตัวแปรคำอธิบาย

13.2 กฎเกณฑ์สำคัญที่ต้องจำ

  1. memberShare + employeeShare ต้องรวมกันเป็น 100 — ตรวจสอบที่ App Layer (ไม่มี DB constraint)
  2. ต้องระงับก่อนลบ — ลบได้เฉพาะ Entity ที่มีสถานะ Inactive
  3. ห้ามมีสัญญาซ้ำ — คู่ Member-Employee เดียวกัน มีสัญญา Active ได้แค่ 1 ฉบับ
  4. Decimal → Number — ทุกครั้งที่ดึงข้อมูลจาก Prisma ต้อง .toNumber()
  5. Date → ISO string — ทุก DateTime ต้อง .toISOString() ก่อนส่งให้ Client
  6. photoUrl ไม่ถูกดึงในหน้า List — ดึงเฉพาะเมื่อดู/แก้ไขข้อมูลรายบุคคล

13.3 Flow ที่ต้องระวัง

🔴 การรับซื้อน้ำยาง:

  1. พิมพ์รหัสผู้ขาย → Hook useSellerLookup ค้นหาและแสดงชื่อ + สัดส่วน
  2. กรอกน้ำหนัก + %เนื้อยางแห้ง → คำนวณ realtime ที่ Client
  3. กดยืนยัน → เปิด ConfirmDialog → ส่ง POST ไปที่ API
  4. API สร้าง Purchase + เพิ่มเงินเข้ากระเป๋า Member ใน Transaction เดียว
  5. แสดง Receipt (ซ่อนปกติ แสดงเมื่อสั่งพิมพ์) → กด "พิมพ์ใบเสร็จ" → window.print()

🔴 การเบิกเงิน:

  1. พิมพ์รหัสสมาชิก → Hook useMemberLookup ค้นหาและแสดงยอดเงินสะสม
  2. กรอกยอดเบิก → API ตรวจสอบว่ายอดเงินเพียงพอ
  3. API สร้าง Withdrawal + หักเงินจากกระเป๋า Member ใน Transaction เดียว
